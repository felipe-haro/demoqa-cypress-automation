# [DEF-002] Text Box keeps showing stale output after an invalid re-submission

**Labels:** `bug` `severity:medium` `priority:low` `area:text-box`

## Summary

After a valid submission, the output panel shows the submitted data. If the user then submits the form again with an
invalid email, the email field is flagged as invalid but the old output stays on screen unchanged. This can make the
user believe that the new, invalid value was accepted.

## Environment

- URL: https://demoqa.com/text-box
- Runner: Cypress 15.21.1, Electron 138 (headless), viewport 1366×900
- First observed: 2026-09-26 · Reconfirmed: 2026-09-28 (`npm run test:known-defects`)

## Preconditions

A previous valid submission has already filled the output panel.

## Steps to reproduce

1. Open `https://demoqa.com/text-box`.
2. Fill in Full Name `Ana Souza`, Email `ana.souza@qa.example.com` and both addresses, then click **Submit**.
   The output panel shows the submitted data.
3. Replace the email with `not-an-email` and click **Submit** again.

## Expected result

The output panel is cleared, or updated to match the current invalid state, because the latest submission is invalid.

## Actual result

The email field gets the red `field-error` border, but the output panel still shows the previous submission
(`Email:ana.souza@qa.example.com`, the name and both addresses).

## Severity / Priority

- **Severity:** Medium. The page shows data that does not match the current form state, which can mislead the user.
- **Priority:** Low. This is a demo component with no persistence and no downstream effect.

## Reproducibility

Always. The automated test failed on every recorded run of `npm run test:known-defects`.

![Email field flagged invalid while the output panel still shows the previous submission](../evidence/DEF-002-stale-output.png)

- Failure output:

```
AssertionError: Timed out retrying after 8000ms: Expected [ <p#name.mb-1>, 3 more... ] not to exist in the DOM, but it was continuously found.
```

## Workaround

None known.

## Notes / suspected cause

Hypothesis: the output panel is rendered only on a valid submission. The invalid path flags the email field but
does not clear the output that is already on screen.

## Suggested fix / acceptance criteria

- [ ] Submitting the form with an invalid field clears the output panel that was rendered before.
- [ ] When the output panel is visible, it always shows only the most recent valid submission.
